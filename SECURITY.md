# Security Policy

## What this repo is

`agent-deployments` is a **docs + templates producer** — it has no runnable
application of its own. It publishes `catalog.yaml` (auto-generated by
`scripts/generate_catalog.py` from recipe and capability frontmatter — never
hand-edited), recipe markdown, and capability docs/templates that
`agent-scaffold` consumes to generate other people's projects.

## Reporting a Vulnerability

If you discover a security issue, please report it responsibly rather than
opening a public issue.

**How to report:**
1. Open a [GitHub Security Advisory](https://github.com/jagguvarma15/agent-deployments/security/advisories/new) (preferred — keeps details private until resolved)
2. Or email the maintainer directly via the contact on their GitHub profile

Please include a description of the issue, steps to reproduce, the potential
impact, and a suggested fix if you have one.

We aim to acknowledge reports within 3 business days and publish a fix or
advisory within 14 days of confirmation.

## What's actually gated

- **Catalog Drift Check** (`.github/workflows/catalog-drift.yml`) runs on
  every push and pull request to `main`: it re-runs
  `scripts/test_catalog_validation.py`'s self-tests, regenerates
  `catalog.yaml`, and fails the build if the committed file doesn't match —
  the repo's primary correctness gate.
- **`pip-audit`** (same workflow) scans `scripts/requirements.txt` — the one
  Python dependency (`PyYAML`) the catalog generator uses.
- **Recipe Smoke Tests** (`recipe-smoke.yml`) are manual-dispatch only today,
  pending the reference implementations and API-key secrets they need.
- **Blueprints Bump** / **Sync Blueprints** keep the embedded upstream
  `agent-blueprints` catalog current on a schedule and on release, respectively.

There is no Dependabot, no lockfile (this repo has one pinned floor,
`PyYAML>=6.0`, in `scripts/requirements.txt`), and no `Makefile` — this repo
ships docs and templates, not a runnable application with its own dependency
tree to lock.

## Scope

Recipe and capability markdown is treated as trusted input by every
downstream consumer — `agent-scaffold` bundles a copy in the wheel and also
fetches `catalog.yaml` directly at runtime. A vulnerability here typically
means: a recipe or capability doc that, once generated by `agent-scaffold`,
produces an insecure default in the *generated* project (an open CORS policy,
a missing auth check, a weak default secret). For guidance on what "secure"
means for a generated agent, see
[`docs/cross-cutting/security-hardening.md`](docs/cross-cutting/security-hardening.md)
— that document is recipe-authoring guidance for the prototypes this repo
produces, not a description of this repo's own build pipeline (that's this
file).

## Supported Versions

Only the latest content on `main` is supported.
